Key Concepts

  • Use the simple Action Animate Transform script for basic, single-property animations, and the more complex Animation Controller for multi-part or highly-controlled animations
  • Looping animations should have matching beginning and end key frames to avoid a visual glitch/snap on repeat
  • Child object position is always relative to its parent, so animated objects should be nested one level below an empty parent object to avoid all duplicates collapsing to the same world position
  • 3D object anchor points (pivots) are stored in the source file and must be fixed in the original modeling program (e.g., Blender), not in Unity
  • Squash and stretch animations must preserve volume by compensating scale changes in perpendicular axes
  • Unity events are the underlying mechanism for triggering interactions, and can carry data such as the exact name (string) of an animation clip to play
  • Animator states are controlled via a state machine; use a 'stop' state and default state settings to control when animations play once versus loop
  • Foundational animation and rigging concepts (like parenting/hierarchy) transfer across programs, so students shouldn't fear learning new tools

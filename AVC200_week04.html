Key Concepts

  • VR headsets must be reconnected to each computer's account individually via Steam VR
  • VR rendering is twice as expensive since each eye needs a separately rendered image, creating stereoscopic depth perception
  • Motion sickness in VR occurs when visual input doesn't match the body's spatial/balance senses, making teleportation preferable to joystick movement
  • Tags (like Player) and Layers (like Ground) are two distinct ways to categorize game objects in Unity
  • Character controllers need colliders and layer masks to correctly detect ground contact for jumping
  • Input Trigger Zones with colliders marked 'Is Trigger' let objects send Enter/Exit/Stay events to control gameplay logic
  • Turning objects on and off (GameObject.SetActive) is one of the most powerful and common tools for building interactivity
  • Avoid the 'big bang' approach—test each new component incrementally rather than building everything before testing
  • Modular design applies to both code (Event Game Toolkit) and 3D assets, letting pieces be combined in many configurations like Lego

Key Concepts

  • Cover the required basics first, then embellish with extra polish if time allows
  • Turning down computer/system volume does not affect what OBS records; OBS captures audio before it reaches speakers
  • Sprites are unlit by default while meshes are lit by default, affecting how they respond to scene lighting
  • Lowering the 'pixels per unit' value on a sprite makes it larger in Unity
  • The Cinemachine package handles camera-follow logic with adjustable damping (springiness) and dead zones
  • Setting up a character controller requires a capsule, character controller component, and an input action asset like EGTK
  • Unity's UI canvas separates screen space (2D overlay) from world space (3D scene), and 'Screen Space Camera' with scale set to 1920x1080 keeps UI elements stable
  • Choose conservative, readable fonts for on-screen text rather than overly stylized ones, since the goal is readability

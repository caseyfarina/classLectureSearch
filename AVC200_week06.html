Key Concepts

  • Building a game compiles C# code into a standalone Windows executable (.exe)
  • Test building early helps catch build-specific errors before deadlines
  • Distributing a built game requires zipping the entire build folder, not just the executable
  • The Unity Profiler shows real-time performance data like frame time and CPU/GPU usage
  • 60 FPS requires each frame to compute in about 17 milliseconds
  • Scripts should be treated like black boxes with exposed serialized fields for easy customization
  • 2D physics and colliders are separate systems from their 3D counterparts in Unity
  • Normalized animation curves (0 to 1) can be scaled and randomized for varied, reusable effects

Key Concepts

  • Development of personal taste and aesthetic matters more than technical skill, since tools make execution increasingly easy
  • Using existing intellectual property is allowed under fair use, but original ideas are encouraged to build a distinct creative voice
  • Export settings from Blender can accidentally include extra cameras or lights, polluting Unity scenes
  • Material tiling must match real-world scale references, or environments will look proportionally wrong
  • Backface culling is on by default in Unity but off in Blender, requiring manual material adjustments for double-sided visibility
  • Particle systems need emission/glow, color-over-lifetime, noise, and trails to convincingly simulate effects like fire, electricity, or steam
  • Custom particle sprites (simple soft blobs made in Photoshop) look far more professional than Unity's default particle image
  • Games must be designed so new players can navigate and find content within a reasonable time without needing outside knowledge

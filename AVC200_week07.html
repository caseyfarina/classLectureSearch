Key Concepts

  • Variables (int, float, string, bool) store different types of data in memory and must be properly named and typed
  • Methods/functions are verb-like actions that can take parameters to perform operations with data
  • A Collection Manager pattern tracks persistent game state like coins or health using increment/decrement functions
  • Prefabs with event-based interactivity must be duplicated (not dragged from assets) to preserve Unity event references
  • Thresholds trigger Unity events when a tracked value crosses a set point, enabling doors, bridges, and other gated content
  • Use PlayOneShot for overlapping sound effects (like coin pickups) and Play for continuous audio like music
  • Particle systems should use World simulation space when attached to moving objects to avoid visual artifacts
  • Bloom/glow effects require both emissive material values above a threshold and post-processing enabled on the camera

Key Concepts

  • Unity's default scene has ambient/environment lighting that must be manually disabled to achieve true darkness
  • Soft particles prevent hard intersection edges where fog/smoke meets geometry
  • Big objects should move slowly to visually communicate scale (e.g., giant doors)
  • Diegetic elements exist within the game world and can be seen by characters; non-diegetic elements are only visible to the player
  • Consistent interaction design (walking up vs. clicking) helps players learn how a game's interface works
  • Mixing 2D sprites in 3D space is a valid and effective art style choice, not a limitation
  • Randomizing particle rotation, scale, and overlap creates more convincing amorphous effects like fog or blobs
  • Scope management is critical: prioritize core functionality before adding polish, since project time is always limited
